    How these were built

    The same three rules run through every project on this page.

    • Start from a real workflow

      Each build begins with a task people actually do by hand — onboarding a client, qualifying a lead, writing up a meeting, following up with a customer.

    • Keep the reliable core

      When an integration causes friction, the build is simplified to the part that works and the rest is added later, as in the Make project.

    • Say what's live and what isn't

      Demo data is labelled as demo data, drafts as drafts, and no performance results are claimed where no live traffic exists.
